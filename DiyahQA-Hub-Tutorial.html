Bab 1
Memulai DiyahQA Hub

1.1 Instalasi & Membuka Aplikasi

  1. Download file DiyahQA Hub-1.0.0-arm64.dmg
  2. Double-click DMG → drag ikon ke folder Applications
  3. Klik kanan aplikasi → pilih Open (untuk bypass Gatekeeper)
  4. Klik Open pada dialog konfirmasi keamanan macOS
  5. Aplikasi terbuka dan database lokal dibuat otomatis
💡 Tips: Jika muncul "tidak dapat dibuka karena developer tidak teridentifikasi", buka System Settings → Privacy & Security → klik "Open Anyway"

1.2 Membuat Proyek Pertama

Sebelum menggunakan fitur apapun, buat proyek terlebih dahulu. Proyek adalah kontainer untuk semua test case, bug report, dan test plan.

  1. Di sidebar kiri, klik ikon + di bagian PROJECTS
  2. Isi nama proyek dan deskripsi singkat
  3. Klik Simpan
📋 Contoh
Nama ProyekJobseeker App v2.0
DeskripsiTesting siklus release Agustus 2026 — fitur Register, Login, dan Dashboard kandidat

2.2 Import Test Case dari CSV

Jika sudah punya test case di spreadsheet (Excel/Google Sheets), bisa diimport langsung.

  1. Siapkan file CSV dengan header: NO, TITLE, MODULE, SECTION, SCENARIO, EXPECTED RESULT, STATUS, WEBSITE, TEST DATA, EVIDENCE, NOTE
  2. Di halaman Test Cases, klik tombol Import CSV
  3. Pilih file CSV
  4. Sistem akan import semua baris secara otomatis
📋 Contoh Format CSV
NOTITLEMODULESTATUS
TC-001Login dengan email validAuthPending
TC-002Login dengan password salahAuthPending
TC-003Lupa password — kirim email resetAuthPending

2.3 Import dari Allure JSON

Jika tim sudah menggunakan Allure untuk automation testing, hasilnya bisa diimport langsung.

  1. Dari hasil Allure report, ambil file JSON di folder allure-report/data/test-cases/
  2. Di Test Cases, klik Import Allure
  3. Pilih file JSON Allure
  4. Status akan otomatis dipetakan: passed→Pass, failed→Fail, skipped→Skip

2.4 TC Library — Template Test Case

TC Library menyimpan template test case yang bisa digunakan ulang di berbagai proyek.

  1. Klik TC Library di sidebar
  2. Klik + Tambah ke Library
  3. Isi template dengan scenario umum yang sering digunakan
  4. Saat membuat test case baru, gunakan template dari library untuk menghemat waktu
📋 Contoh Template di TC Library

Judul: Upload File — Validasi Format yang Tidak Didukung

Tags: upload, validasi, file

Scenario:
1. Buka halaman yang memiliki fitur upload
2. Klik tombol Upload
3. Pilih file dengan format tidak didukung (contoh: .exe, .zip)
4. Klik Submit/Upload

Expected Result: Sistem menampilkan pesan error "Format file tidak didukung"

Bab 4
Test Plans & Eksekusi

Test Plan adalah dokumen yang mengelompokkan test case untuk satu siklus pengujian (sprint, release, atau regression).

4.1 Membuat Test Plan

  1. Klik Test Plans di sidebar
  2. Klik tombol + New Test Plan
  3. Isi nama plan, deskripsi, pilih proyek, dan environment (opsional)
  4. Pilih test case yang akan dimasukkan (bisa pilih semua atau spesifik)
  5. Klik Buat Test Plan
📋 Contoh Test Plan
Nama PlanRegression Testing Sprint 12 — Agustus 2026
DeskripsiTesting seluruh fitur yang terdampak perubahan pada release v2.3.0
ProyekJobseeker App v2.0
EnvironmentStaging
Test CasesREG-001 s/d REG-050 (50 test cases)

4.2 Menjalankan Test Plan

Memulai Eksekusi

  1. Klik test plan yang ingin dieksekusi dari daftar
  2. Klik tombol ▶ Mulai untuk mengubah status dari Draft ke Active
  3. Tabel test case akan menampilkan tombol aksi: Pass Fail Blocked Skip

Mengisi Status Test Case

TombolArtiCatatan
PassTest berhasilTidak perlu catatan
FailTest gagal/bug ditemukanModal akan muncul untuk isi catatan kegagalan
BlockedTidak bisa dieksekusiKarena dependency atau environment bermasalah
SkipDilewatiOut of scope atau tidak relevan
⚠️ Catatan: Jika klik Fail, akan muncul modal untuk mengisi catatan kegagalan. Isi dengan deskripsi singkat bug yang ditemukan untuk dokumentasi yang lebih lengkap.

Menyelesaikan Test Plan

  1. Setelah semua test case selesai dieksekusi, klik tombol ✅ Selesai
  2. Jika masih ada test case "Not Run", sistem akan meminta konfirmasi
  3. Status plan berubah menjadi COMPLETED
  4. Progress bar dan statistik (Pass/Fail/Blocked/Not Run) tersimpan
📋 Contoh Hasil Eksekusi
MetrikNilai
Total Test Cases50
Pass ✅42 (84%)
Fail ❌5 (10%)
Blocked 🔶2 (4%)
Not Run ⚪1 (2%)
Pass Rate84%

5.1 Membuat Requirement

  1. Klik Requirements di sidebar

  3. Isi kode, judul, deskripsi, prioritas, dan status
  4. Klik Simpan

DeskripsiSistem harus memungkinkan user baru mendaftar menggunakan email yang belum terdaftar sebelumnya

StatusActive

5.2 Menghubungkan Requirement ke Test Case

  1. Buka detail requirement yang ingin dihubungkan
  2. Di bagian Linked Test Cases, klik Tambah Link
  3. Pilih test case dari daftar yang tersedia
  4. Klik Simpan
📋 Contoh Traceability Matrix
RequirementTest CaseStatus TC
REQ-001: Registrasi email validREG-001: Modal privasi munculPass

6.2 Transfer Bug ke Plane

Transfer Satu Bug

  1. Di tabel Bug Reports, temukan bug yang ingin ditransfer
  2. Klik ikon ✈️ di kolom Actions
  3. Muncul modal input email assignee — isi email atau kosongkan jika tidak perlu
  4. Klik Transfer
  5. Kolom Plane Status akan menampilkan badge Backlog setelah berhasil

Transfer Banyak Bug (Bulk)

  1. Centang checkbox di beberapa baris bug
  2. Toolbar akan menampilkan tombol ✈️ Transfer ke Plane (N)
  3. Klik tombol tersebut dan konfirmasi dialog
  4. Sistem memproses satu per satu secara berurutan
  5. Ringkasan hasil (berhasil/gagal/dilewati) ditampilkan setelah selesai
💡 Tips: Bug yang sudah pernah ditransfer (sudah punya Plane Issue ID) akan di-skip secara otomatis dalam bulk transfer untuk menghindari duplikasi.

Bab 7
API Lab

API Lab adalah modul untuk belajar, menguji API secara manual, mengelola collection, dan generate automation script Playwright.

7.1 Tab Manual Testing

Kirim HTTP request langsung dari aplikasi — mirip seperti Postman.

  1. Klik API Lab di sidebar
  2. Pilih tab Manual Testing
  3. Pilih metode HTTP (GET, POST, PUT, DELETE, dll.)
  4. Isi URL endpoint
  5. Tambahkan Headers jika diperlukan (contoh: Authorization, Content-Type)
  6. Isi Request Body untuk POST/PUT
  7. Klik Send
  8. Respons akan ditampilkan di panel bawah
  9. Klik Save untuk menyimpan ke Collections
📋 Contoh Request Login
MethodPOST
URLhttps://api.jobseeker.company/auth/login
HeadersContent-Type: application/json
Body{"email": "test@example.com", "password": "Test123!"}
Expected Response200 OK dengan token JWT

7.2 Tab Collections

Collections menyimpan request yang sudah pernah dikirim dari Manual Testing. Gunakan untuk menjalankan ulang request tanpa harus mengisi ulang.

💡 Cara menambah collection: Kirim request dari tab Manual Testing → klik tombol Save → request tersimpan otomatis ke Collections.

7.3 Tab Environments

Simpan variabel environment (base URL, token, dll.) yang bisa digunakan di semua request.

📋 Contoh Environment Variables
VariabelNilai (Staging)Nilai (Production)
BASE_URLhttps://staging-api.jobseeker.companyhttps://api.jobseeker.company
AUTH_TOKENeyJhbGci... (staging token)eyJhbGci... (prod token)

7.4 Tab OpenAPI Import

Import spesifikasi OpenAPI/Swagger untuk generate collection otomatis.

  1. Klik tab OpenAPI Import
  2. Paste URL Swagger JSON atau upload file .json/.yaml
  3. Klik Import
  4. Semua endpoint akan ter-generate sebagai collection

7.5 Tab Automation

Generate kode Playwright otomatis dari request yang ada di collection.

  1. Klik tab Automation
  2. Pilih request dari collection
  3. Klik Generate Script
  4. Kode Playwright test siap di-copy ke project automation

Sub-modulKonten

📋 Contoh Kode Playwright (Login Test)
import { test, expect } from '@playwright/test';

test('Login berhasil dengan kredensial valid', async ({ page }) => {
  await page.goto('https://app.jobseeker.company/login');

  await page.fill('[data-testid="email"]', 'user@example.com');
  await page.fill('[data-testid="password"]', 'Password123!');
  await page.click('[data-testid="login-btn"]');

  await expect(page).toHaveURL('/dashboard');
  await expect(page.locator('h1')).toHaveText('Dashboard');
});

Bab 10
FAQ & Troubleshooting

Pertanyaan Umum

Q: Di mana data aplikasi tersimpan?

Data tersimpan lokal di: ~/Library/Application Support/DiyahQA Hub/testcases.db — file SQLite yang hanya ada di Mac kamu.

Q: Bisakah data dipindah ke Mac lain?

Ya. Copy file testcases.db dari Mac lama ke path yang sama di Mac baru.

Q: Tombol Fail di Test Plan tidak bisa diklik?

Pastikan status Test Plan adalah Active (sudah klik ▶ Mulai). Tombol aksi hanya muncul saat status Active.

Q: Transfer bug ke Plane gagal dengan error "Invalid character"?

API Key mengandung karakter tersembunyi. Solusi: buka ⚙️ Plane Settings → hapus dan ketik ulang API Key secara manual (jangan paste) → Simpan.

Q: Status di kolom Plane Status menampilkan UUID bukan nama status?

Ini terjadi pada data lama. Klik ikon 🔄 di header kolom Plane Status untuk sync ulang — status akan diperbarui dengan nama yang benar.

Q: Server Plane timeout (Gateway 504)?

Server Plane sedang down. Tunggu hingga server kembali online sebelum mencoba transfer atau sync ulang.

Q: Notifikasi Google Chat tidak terkirim?

Periksa: (1) Webhook URL sudah diisi di Plane Settings, (2) URL webhook masih valid dan aktif di Google Chat, (3) Koneksi internet aktif saat transfer.

Q: Bagaimana cara update API Key Plane?

Klik tombol ⚙️ Plane di halaman Bug Reports → hapus isi field API Key → ketik API Key baru → klik Simpan.

Q: Collections di API Lab kosong?

Collection diisi melalui tab Manual Testing. Kirim request → klik tombol Save → request tersimpan ke Collections.
